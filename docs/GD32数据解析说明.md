# GD32 传感器数据 · Java 后端解析说明

> 适用版本：iot-java-local-storage-1.0.0
> 核心类：`TcpDeviceServer` · `SensorService` · `DeviceConnectionManager`

---

## 一、数据是怎么到达后端的

```
GD32F470 (MCU)
    │  每 200ms 读一次 I2C/GPIO 传感器
    │  每 7 秒打包 JSON，通过 UART 发 AT 指令
    ▼
ESP32-C3 (WiFi STA)
    │  AT+CIPSEND=0,123  →  TCP 8081
    ▼
Java Spring Boot ServerSocket(8081)
    │
    ▼
TcpDeviceServer.acceptLoop() → handleClient()
```

板子实际发送的是**裸 TCP 裸 JSON**（不带 HTTP 头），例如：

```json
{"project":20,"name":"Classroom","temperature":25.0,"humidity":60.0,"light":500,"pir_detected":0}
```

后端同时兼容带 HTTP POST 头的完整帧（见第三节）。

## 二、TCP 收包与拆包

### 2.1 连接管理

`TcpDeviceServer` 用 `@PostConstruct` 启动一个守护线程：

```java
// TcpDeviceServer.java:58-63
@PostConstruct
public void start() {
    Thread thread = new Thread(this::acceptLoop, "iot-tcp-accept");
    thread.setDaemon(true);
    thread.start();
}
```

`acceptLoop()` 监听 8081，每个新连接丢进 `CachedThreadPool` 跑 `handleClient()`：

```java
// TcpDeviceServer.java:70-82
Socket socket = ss.accept();
socket.setKeepAlive(true);
pool.submit(() -> handleClient(socket));
```

TCP keepalive 调优（[line 74-80](file:///d:/iot-java-local-storage-no-db-fixed/iot-java-local-storage-no-db/src/main/java/com/example/iot/tcp/TcpDeviceServer.java#L74-L80)）：空闲 30s 开始探测，每 10s 一次，3 次无应答判定死链。避免手机热点/NAT 老化后挂着假连接。

### 2.2 循环读 + 缓冲区拼接

`handleClient()` 用 `ByteArrayOutputStream` 当缓冲区，`socket.setSoTimeout(3000)` 设置 3 秒读超时：

```java
// TcpDeviceServer.java:92-105
ByteArrayOutputStream buffer = new ByteArrayOutputStream();
socket.setSoTimeout(3000);
byte[] temp = new byte[4096];

while (...) {
    n = in.read(temp);          // 从 socket InputStream 读原始字节
    if (n < 0) break;
    if (n > 0) buffer.write(temp, 0, n);
```

ESP32-C3 可能分多段发一个报文，所以后端必须循环拼到完整才能处理。

### 2.3 三种报文兼容拆包

拿到缓冲区字节后，进入拆包逻辑（[line 112-153](file:///d:/iot-java-local-storage-no-db-fixed/iot-java-local-storage-no-db/src/main/java/com/example/iot/tcp/TcpDeviceServer.java#L112-L153)）：

```java
byte[] bytes = buffer.toByteArray();

// 在 bytes 里找 \r\n\r\n
int headerEnd = indexOf(bytes, HEADER_END, consumed);
```

#### 情况 A：完整 HTTP POST 帧

```
POST /device/update HTTP/1.1\r\n
Host: 192.168.43.10:8081\r\n
Content-Type: application/json\r\n
Content-Length: 95\r\n
\r\n
{"project":20,"temperature":25.0,...}
```

- 找到 `\r\n\r\n`（header 和 body 分隔符）
- 读 `Content-Length` 得到 body 长度
- 精确切出 `byte[] body` → 进 `processRequest()`

#### 情况 B：裸 JSON（板子实际发的）

```
{"project":20,"temperature":25.0,...}
```

- 缓冲区里**找不到** `\r\n\r\n`
- 看首尾是不是 `{` 和 `}`
- 整个缓冲区直接当 body → 进 `processRequest()`

#### 情况 C：Content-Length 超声称的长度但 body 已完整

ESP32-C3 分片或 CL 算错时，只要 body 首尾是 `{` `}`，后端就提前处理不死等。

## 三、processRequest：校验 + 解析 + 存

这是核心入口（[line 190-240](file:///d:/iot-java-local-storage-no-db-fixed/iot-java-local-storage-no-db/src/main/java/com/example/iot/tcp/TcpDeviceServer.java#L190-L240)）。

### 3.1 校验阶段

```java
// 校验 1：headers 必须包含 POST /device/update，或者根本没 headers（裸 JSON）
if (!headers.contains("POST /device/update") && !headers.isEmpty()) {
    sendHttp(socket, 404, "Not Found");
    return;
}

// 校验 2：body trim 后不能为空
String bodyStr = new String(body, StandardCharsets.UTF_8).trim();
if (bodyStr.isEmpty()) {
    sendHttp(socket, 400, "Bad Request");
    return;
}
```

### 3.2 Jackson 反序列化

```java
Map<String, Object> json = objectMapper.readValue(bodyStr, new TypeReference<>() {});
```

Jackson 把 JSON 转成 `Map<String, Object>`，例如：

```json
{"project":20,"name":"Classroom","temperature":25.0,"humidity":60.0}
```

变成：

| Key | Value | Java 类型 |
|-----|-------|----------|
| project | 20 | Integer |
| name | "Classroom" | String |
| temperature | 25.0 | Double |
| humidity | 60.0 | Double |

### 3.3 字段拆分

```java
Object projectObj = json.remove("project");      // 20
int projectId = projectObj == null ? 0 : Integer.parseInt(String.valueOf(projectObj));

Object nameObj = json.remove("name");             // "Classroom"
String projectName = nameObj == null ? defaultProjectName(projectId) : String.valueOf(nameObj);

Map<String, Object> sensorData = new LinkedHashMap<>(json);  // 剩余全是传感器数据
```

| 字段 | 去向 |
|------|------|
| `project` | → `projectId`，标识设备归属（0=通用, 20=智能教室） |
| `name` | → `projectName`，显示用名称 |
| 其余所有字段 | → `sensorData`，存进 data/ 本地文件 |

`defaultProjectName()` 做了 projectId → 中文名映射：

```java
case 0  -> "基础 IoT 控制"
case 13 -> "智能宠物屋"
case 15 -> "智能窗户"
case 16 -> "智能垃圾桶"
case 17 -> "智能农场"
case 20 -> "智能教室"
case 25 -> "智能无人机"
default -> "Project " + projectId
```

### 3.4 在线注册

```java
boolean wasRegistered = connectionManager.isOnline(projectId);
connectionManager.register(projectId, socket);   // projectId → socket 绑定
if (!wasRegistered) {
    deviceService.onConnected(projectId, projectName, socket);  // 首次连接触发
}
connectionManager.touch(projectId);               // 刷新 lastActiveMs
```

**在线判断**（`DeviceConnectionManager.isOnline()`）：
- 真实 TCP 连接还活着 → 在线
- 或者 90 秒内有过数据上报（心跳宽限期）→ 在线

兼容板子短连接上报场景：板子连上来、发 JSON、关连接，90 秒内前端仪表盘仍显示"在线"。

### 3.5 存储

```java
long recordId = sensorService.save(projectId, projectName, sensorData);
```

`SensorService.save()`（[SensorService.java:30-36](file:///d:/iot-java-local-storage-no-db-fixed/iot-java-local-storage-no-db/src/main/java/com/example/iot/service/SensorService.java#L30-L36)）：

```java
long id = repository.save(projectId, projectName, sensorData);  // 写本地 data/ 文件
alertService.detectAndSave(projectId, projectName, sensorData);   // 阈值告警检测
```

没有数据库，数据序列化存到 `data/` 目录。

### 3.6 通信日志

```java
commLogManager.addLog(CommunicationLogManager.Direction.RECEIVED,
        projectId, remoteAddr, bodyStr);
```

环形缓冲区（MAX=200），供前端通信日志面板每 2 秒轮询展示。

### 3.7 回 HTTP 200 + 命令下发

```java
sendHttp(socket, 200, "OK", projectId);
```

响应体有两种情况：

| 情况 | 响应 body |
|------|----------|
| 前端没发过命令 | `{"status":"OK"}` |
| 前端发过命令（排队中） | `{"status":"OK","cmd":"L"}` |

命令通过 `connectionManager.pollPendingCommand(projectId)` 取出并塞进响应 JSON。板子下次上报时必读 HTTP 响应，因此命令必然送达。

### 3.8 异常兜底

`processRequest()` 整个包在 try-catch 里，任何 Jackson 解析异常、空指针都会回 HTTP 400：

```java
catch (Exception e) {
    log.warn("Invalid device request: {}", e.getMessage());
    sendHttp(socket, 400, "Bad Request");
}
```

## 四、完整时序图

```
GD32/ESP32-C3                     Java 后端                      前端
     │                               │                            │
     │──── TCP connect :8081 ──────▶│                            │
     │                               │ acceptLoop.accept()         │
     │                               │ pool.submit(handleClient)   │
     │                               │                            │
     │──── raw JSON bytes ──────────▶│                            │
     │   (可能分多段到达)              │ handleClient()              │
     │                               │   buffer.write(temp,0,n)    │
     │                               │   循环直到找到完整报文        │
     │                               │                            │
     │                               │─── processRequest() ───▶   │
     │                               │   Jackson.readValue → Map   │
     │                               │   json.remove("project")   │
     │                               │   json.remove("name")      │
     │                               │   sensorData = 剩余字段     │
     │                               │                            │
     │                               │─── connectionManager        │
     │                               │     .register()             │
     │                               │─── sensorService.save()     │
     │                               │     → repository.save()     │
     │                               │     → alertService.detect() │
     │                               │─── connectionManager.touch()│
     │                               │─── commLogManager.addLog()  │
     │                               │                            │
     │◀──── HTTP 200 + JSON ────────│                            │
     │   {"status":"OK"}             │                            │
     │                               │                            │
     │                               │                            │
     │                               │    (若前端之前发过命令)        │
     │                               │                            │
     │                               │◀── POST /api/command/20 ───│
     │                               │     body: {"cmd":"L"}       │
     │                               │  connectionManager          │
     │                               │    .enqueueCommand(20,"L")  │
     │                               │                            │
     │                               │    ... 板子下次上报时 ...     │
     │                               │                            │
     │◀──── HTTP 200 ───────────────│                            │
     │   {"status":"OK","cmd":"L"}   │  pollPendingCommand()       │
     │                               │                            │
     │  (GD32 解析 cmd → 开灯)         │                            │
```

### 完整 HTTP POST（带 headers）

```

Content-Type: application/json\r\n
Content-Length: 101\r\n
\r\n
{"project":20,"name":"Classroom","temperature":25.0,"humidity":60.0,"light":500,"pir_detected":0}
\r\n\r\n
```

### 裸 JSON（板子实际发的）

```
{"project":20,"name":"Classroom","temperature":25.0,"humidity":60.0,"light":500,"pir_detected":0}
```

后端两种都能正确解析。
